# 12306 余票监控：说一句"几号从哪到哪、几点"，有票立刻报

国庆、春运这类高峰，热门车次的二等座早就卖完了，但退票和没付款超时释放的座位会不断冒出来，**每次只存在几十秒到几分钟**。用户需要的是：有人替他一直盯着，一出现就用一眼能定位的格式告诉他，他在手机 App 里直接下单。本 skill 就干这件事；它不替用户下单。

数据来源是 12306 官方余票，通过 `12306-mcp`（`npx -y 12306-mcp`，Node 18+，第一次运行会自动下载）查询，由 `scripts/watch.mjs` 封装好了轮询、去重、冷却和自动停止。

## 1. 从用户的话里拿到参数

| 参数 | 怎么定 | 默认 |
|---|---|---|
| 日期 `--date` | 用户说的日期。相对日期（明天、周五）按**北京时间**算：本机时区可能不是北京，用 `TZ=Asia/Shanghai date` 取今天 | 必填 |
| 出发 / 到达 `--from --to` | 城市名就查全市所有车站（「杭州」含杭州东/西/南）；用户点名车站就写站名 | 必填 |
| 时段 `--start --end` | "早上" 05:00–12:00，"中午以前" 05:00–12:00，"下午" 12:00–18:00，"晚上" 17:00–24:00，"下午两点以前" --end 14:00 | 全天 |
| 人数 `--min` | 几个人一起走就填几（几张票都要在同一班车上才算有票） | 1；用户提过同行人数就用那个 |
| 座位 `--seats` | 默认二等座、一等座、优选一等座；用户说"商务座也行"就加上，"站票也行"用 `all` | 二等/一等/优选一等 |
| 车型 `--types` | 默认只看高铁动车 `GD`；用户说普速/卧铺也行就传空字符串 `--types ""` | GD |
| 排除车站 `--exclude-stations` | 离目的地太远的站，比如去苏州老城时排除 `苏州南` | 无 |

日期、出发地、目的地缺一个就先问，其他都用默认值直接开始，并在第一条回复里说清楚按什么条件盯的（比如「按 2 人、二等/一等座、05:00–14:00 盯」），用户要改再改。

## 2. 先查一次快照，告诉用户现状

```bash
node ~/.claude/skills/train-ticket-watch/scripts/watch.mjs \
  --date 2026-10-01 --from 杭州 --to 南京 --start 05:00 --end 14:00 --min 2 --once
```

输出里：
- 以 `**HH:MM 发车**` 开头的行：现在就满足条件的车次，直接报给用户；
- `不满足条件但还有票的`：只剩商务座、无座或张数不够的，作为备选简单提一句；
- `ALL=...`：当前满足条件的组合，下一步要传给 `--prev`。

如果时段内 0 班车：可能是日期超过预售期（12306 一般提前 15 天开售）或站名写错，先跟用户确认。

## 3. 后台启动监控

用 Bash 的 `run_in_background: true` 跑（前台会阻塞对话）：

```bash
node ~/.claude/skills/train-ticket-watch/scripts/watch.mjs \
  --date 2026-10-01 --from 杭州 --to 南京 --start 05:00 --end 14:00 --min 2 \
  --interval 10 --prev "<上一步的 ALL= 内容>"
```

脚本行为：
- 每 `--interval` 秒（默认 10）查一次；查询出错自动退避到 60 秒，防止被 12306 限流。
- 只有某个「车次:座位」**从不满足变成满足**时才算新票（`--prev` 里已经报过的不重复报）；同一个组合 5 分钟内只报一次（`--cooldown 300`），因为同一张退票常常在几十秒里反复出现又消失，每次都报会刷屏。
- 有新票：打印 `HIT` + 提醒行 + `ALL=`，然后退出；到了 `--until`（默认出发日期的 `--end` 时刻）打印 `STOP` 退出。
- 日志在 `~/.cache/train-ticket-watch/<日期>_<出发>-<到达>.log`，用户问"刚才查了没有"时看最后几行。

## 4. 收到后台任务结束通知后：马上报，马上重启

后台任务一结束就会通知你。读输出文件，然后：

1. **HIT**：立刻用下面的格式把每一行报给用户，**发车时间放最前面并加粗**，因为用户是在 App 的车次列表里按时间找车的：

   > **09:48 发车** · G818 · 杭州东 → 南京南（11:03 到）· 一等座 225 元 · 剩 2 张

   同时调用 `PushNotification`（用户可能没盯着终端；如果终端正开着，工具会自动跳过）。回复要短，不要附带长段解释。
2. **紧接着重启监控**，`--prev` 传这次输出的 `ALL=` 那一串，其他参数不变。这一步不要等用户回复，因为退票随时会再冒出来。
3. **STOP**：告诉用户已经到点停止，问要不要换时段或日期继续盯。
4. **ERROR 或异常退出**：看日志最后几行，修好参数后重启；12306-mcp 偶尔初始化失败，直接重跑即可。

## 5. 什么时候停

- 用户说「停」「不用了」，或者**确认出票成功**（订单里已经有车厢号和座位号，或者显示「已出票」）：
  ```bash
  pkill -f "train-ticket-watch/scripts/watch.mjs"
  ```
  用户手动停掉的任务在通知里会显示 exit code 144，这是正常的，跟用户说一句「是我手动停的」即可。
- 用户只说「抢到了」「下单了」：**先别停**。第三方 App 下单后还要等出票，可能失败退回。继续盯着，同时请用户确认出票。如果他刚抢的那班车又冒出同样张数的票，提醒他看一下订单是不是被释放了。

## 6. 第一次提醒时顺带告诉用户的几件事（只说一次）

- **手抢要快**：退票通常只停留几十秒。App 停在该车次的下单页，提前勾好乘车人，看到提醒直接提交。
- **候补比手抢快**：在 12306 或第三方 App 里给目标车次加候补，有座位时系统会自动兑现。多人候补只会整单兑现，不会只兑现一部分。候补最晚截止到开车前 2 小时（[12306 候补规则](https://kyfw.12306.cn/otn/gonggao/alternate.html)）。
- **出票后取消剩下的候补**：候补是预付款的，兑现后会自动出票。取消还没兑现的候补不收费，多出的票退掉要扣手续费。
- **凌晨车的日期**：0–6 点发车的车，在 12306 上要选当天日期。比如 10/1 00:21 的车要选「10 月 1 日」，选 9/30 是搜不到的。
- **多买一站 / 买短补长**：票面发站之后的站可以上车，没坐的那段不退钱（[12306 说明](https://kyfw.12306.cn/otn/gonggao/enterAndExit.html)）；上车后补票要看车上有没有空位，高峰期不一定补得上。

## 常见坑

- **12306-mcp 返回的 `start_date` 是始发站日期**，不是从你这一站发车的日期，别拿它判断车次是哪天的。车次属于哪天，以查询用的 `--date` 为准。
- **同一车次可能出现两行**：列车在同一城市停两个站时（比如杭州东和杭州南），每个站各算一行，价格也不同。
- **别用飞猪 flyai 轮询**：体验模式连续调用会被风控（HTTP 403），价格也只显示到百位。flyai 只适合偶尔查一下，或者拿购买链接。
- **轮询间隔不要低于 5 秒**：10 秒一次在实测中没有被限流；再快只会增加被封的风险，退票出现后能不能抢到主要看手速。
