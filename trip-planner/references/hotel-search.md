# 找酒店：性价比 + 位置，按真实日期的券后价

## 标准
- **位置**：离主线最常用的地铁站步行 ≤500m，或者到主要景点打车 ≤15 元。用户接受「一半地铁一半打车」。
- **价格**：一定查**实际入住日期**的价格。节假日和平时能差一倍，平日价没有参考意义。国内 App 的价格不含税；Trip.com 等国际站会另加约 6% 税费，不能直接比。
- **口碑**：看差评占比和差评内容（隔音、卫生、窗户、床宽），去小红书/知乎搜「店名 避雷」。民宿隔音差要提醒用户。
- **硬条件**：能**寄存行李**（到达早于入住、退房后还要玩一天时必需）；**免费取消截止时间**（订完告诉用户，节假日过了截止时间就不能取消或修改了）；大床/双床、床宽、有没有窗。

## 用 Chrome 查携程（用户已登录的账号能看到会员价和券）
- 用户自己扫码登录，不要替用户输密码；碰到验证码（飞猪经常弹）就停下，让用户在手机 App 里看。
- 列表页的酒店 id 在 `data-offline-hotelid` 属性里。详情页：
  `https://hotels.ctrip.com/hotels/detail/?hotelId=<ID>&checkIn=YYYY-MM-DD&checkOut=YYYY-MM-DD&adult=2&crn=1&children=0`
- 房型卡片用 `[class*=commonRoomCard__]` 取；多晚的价格带「均」字，单晚没有，解析时别依赖「均」。按 `/\n(?:预订|领券订)(?:\n|$)/` 切分每个价格行。
- 关键词搜索有时不过滤，改用左侧「位置」筛选（商圈/地铁站）；搜不到某家店，可以用百度搜「携程 店名」拿 hotelId。
- 连续快速调用会被风控（HTTP 429/403），加间隔、串行查。
- 抖音、美团的酒店套餐券经常不包含市中心的门店，先看适用门店列表再推荐。

## 给用户的结论格式
按预算档位（比如两晚 800/900/1000）各推 1–2 家：店名分店、地址、离哪个站多远、实际日期券后总价、房型（床宽/窗）、口碑要点、能否寄存、取消规则。用户挑好后「一个一个来」看他发的截图：分店、日期、晚数、房型、人数、取消政策逐项对。
